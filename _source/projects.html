Public submission / Open source

RightsReceipt: AI-supported creative licensing.

My RightsReceipt prototype was submitted to the PayPal AI Hackathon. It turns a vague image-use request into reviewable proposed terms, requires creator and buyer approval, calculates a deterministic quote, and reserves payment confirmation for authoritative provider evidence. The fictional test deal uses a USD 425.00 quote.

Read the evidence-backed case study to inspect the seven approval boundaries, a known wrong AI suggestion, and what the tests did and did not establish. The MIT-licensed public repository includes a self-run demonstration and source; the video shows the project.

Important distinction: The local model diagnostic uses real inference on synthetic requests. The application rehearsal injects payment-like responses. Neither is proof of a paid Sandbox invoice, real licensing consent, an issued legal permission, or production use.

Evidence / Corrections / Limits

What can a reader actually verify?

Three different records show why I separate a useful output from a verified outcome:

  1. Measured software behavior: the local-model test record preserves timings, errors, and environment details from an Ubuntu CPU runner. It does not provide a measured speed claim for my Windows laptop or a customer deployment.
  2. A public correction: checking an AI-assisted website change follows a real HTML defect through separate release checks. Passing one set of tests did not establish that the page was valid.
  3. A human review boundary: a poker hand record becomes proposed captions, with source limits and reproducible chip arithmetic. The example does not certify the current video cut or supply missing solver inputs.

For the practical method behind these projects, read AI Works, Human Decides. If you are checking a particular claim, start with the linked record, its date, its original inputs, and what the published test did not evaluate.
