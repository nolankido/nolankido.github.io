Public project / Local AI

Use AI to draft a customer reply, with the owner's policy beside it.

Review Reply Writer is my open-source project for independent cafes and small hospitality businesses. It connects a local Gemma model to a browser workspace where an owner can compare a customer review with a draft, edit the wording, and approve the exact saved reply before copying it for manual posting. The practical task is specific: acknowledge what the customer said without inventing what the business will do.

The application also has a clearly labeled template mode. That makes the review-and-approval workflow available before installing a model, while keeping template text distinct from an AI-generated answer.

Fictional customer / Actual application example

Keep the double charge and the unanswered question visible.

The application's Duplicate billing example begins with a fictional review:

“The coffee was excellent, but I was charged twice. The waiter ignored my question about the bill.”

A useful reply has three details to preserve: the praise, the reported duplicate charge, and the unanswered question. A pleasant apology about “billing” can lose the distinction between an incorrect amount and being charged twice. Offering a refund adds a business decision that the customer's words cannot authorize.

The editor places the saved review and owner policy beside the reply. Its Details to keep panel connects recognized concerns with the customer's original wording. The indicator says Mention detected, which describes a limited wording check. The owner still has to decide whether the response addresses the concern.

The source and recorded review-evidence checks distinguish a specific double-charge acknowledgment from a generic apology. They also keep an ignored question visible when other topics compete for space. These are inspectable implementation choices, not feedback from a real cafe.

AI Works Human Decides

Separate writing, authorization, and approval.

  1. Supply the policy separately. An owner can authorize a particular offer or action. Customer text, a previous reply, and a familiar writing style do not grant new permission.
  2. Save and recheck the wording. Detected unauthorized promises block approval. An edit makes previous detail checks stale until the saved text is checked again.
  3. Read before approving. Approval applies to the exact saved reply and its check version. Editing requires another review.
  4. Copy for manual posting. The application exposes the approved text. It does not publish to a review platform.

That separation is the useful design idea. AI can help express a response; a person remains responsible for the facts, the commitment, and the decision to post it. The owner-workflow record explains how saved text and approval stay connected.

Recorded model output / October 2026

A checker rejected harmless wording and accepted a missing detail.

An earlier real Gemma run used a fictional cold-coffee complaint with a 25-minute wait. Its first candidate said the barista should have addressed the question. The policy check matched part of that phrase as a completed business action and rejected it. The phrase actually described what ought to have happened.

The accepted retry then changed the precise wait into an extended wait. Passing the check did not establish that the reply preserved every important detail. The retained record shows both the rejected candidate and the accepted retry, so the apparent success can be questioned.

A later historical three-case run retained the wait duration and produced three model drafts on first attempts. Both runs precede the current drafting source and contain no recorded human assessments. They establish that particular model calls happened, not a current acceptance rate or proven reply quality.

The reusable lesson: retain rejected attempts and compare accepted wording with the input. A successful status can hide a different kind of error. The AI answer-checking guide applies this habit to other tasks.

Try / Inspect / Adapt

Start with the fictional example.

The setup guide requires Python 3.10 or newer. After downloading and extracting the complete project, Windows users can run py -3 rrw_setup.py --launch; macOS and Linux users can run python3 rrw_setup.py --launch. Template preview needs no model or API key. Actual Gemma drafts require Ollama and downloaded gemma3:4b weights.

Load Duplicate billing with no compensation authorized. Draft, compare the details, and test whether an added refund promise blocks approval after saving. Remove the added promise, read the reply, then approve and copy it. This is a suggested inspection of the current application; the linked 68-second video records an earlier cold-coffee example.

Local inference can give an operator control over model processing. The initial download, computer, and Ollama configuration still matter. The repository explains the local-only setting; a loopback address alone does not verify the runtime's privacy.
