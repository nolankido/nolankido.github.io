Run the same bounded gate without a model or network request

Save the Python checker and the original recorded notes and response in one folder. Run the following with Python 3.10 or later on Windows:

py -3 source-notes-audit.py --self-test
py -3 source-notes-audit.py --check public-notes-action-record.txt

On macOS or Linux replace py -3 with python3. The self-test uses one constructed passing checklist and four deliberately altered controls. The second command reads the actual published record, checks the eleven table rows, and prints a JSON report. Exit code 0 means no targeted flags, 2 means findings, and 1 means an input or execution error. The script does not change any files, send a request, run an AI model, or store a user's notes.

What a person must still decide

This checker is deliberately tied to the eleven known rows and their original source IDs. It cannot judge whether the starting notes were true, verify a project deployment, know whether a deadline was authorized outside the record, or approve publication. The synthetic mistakes test the checker, not the model that produced the original list. A person still needs to inspect the underlying sources, decide whether a task should be done, and confirm any commitments before acting.

The reusable pattern is to preserve the original input, request traceable actions, independently challenge the status and constraints, and keep approval separate from generation. This case documents an actual notes-organization output with a later deterministic audit. It does not report time savings, user satisfaction, a personal planning trial, or a model error rate.

A small method to reuse

Ask for traceable actions and an honest status.

For your own notes, keep an untouched original, label the items, and choose a few meaningful statuses before requesting a checklist. Then trace each action to its input. Look especially for missing conditions, invented owners, and unknowns that have become confident instructions.
