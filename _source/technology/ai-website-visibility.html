How to check search visibility without paying for another dashboard

A website can pass technical checks and still have no measured search improvement. A useful follow-up compares the same reporting period and filters over time, without treating page publication as proof of more clicks. Here is a free procedure that keeps the raw data on your computer.

  1. Export one complete month. In your verified Google Search Console property, open Search results, select Web and the last complete calendar month, then export the daily chart (sometimes Dates.csv) and Pages table. Record the property, date range, filters and export date privately. Queries are optional.
  2. Run the local checker. Save the Python script linked above beside the CSV files. In that folder, this example handles a month-first chart dated like 10/1/2026: 
    py -3 .\gsc-monthly-local-audit.py --month 2026-10 --pages .\Pages.csv --chart .\Dates.csv --chart-date-format mdy
  3. Read the two kinds of totals separately. Property clicks and impressions appear only when the daily chart has every date in the selected month. The Technology, Poker and other section totals are sums of the exported Pages rows, which may be limited. A visible nonbrand Technology click lower bound requires a combined Query + Page export, never a join of separate files. For ISO chart dates, omit the format option; use dmy for explicitly day-first dates.
  4. Repeat without overclaiming. Use the same property, Search type and filters for a later complete month. Check the figures against Search Console before keeping a private scorecard. A month-over-month difference does not establish causation, indexing, AI-generated citations or reader satisfaction.

Try it before exporting private data. Download the synthetic Pages CSV and synthetic Dates CSV. Both contain invented counts, with an extra Synthetic column marked YES. Save the two files beside the Python checker, then run this Windows command:

py -3 .\gsc-monthly-local-audit.py --month 2026-10 --pages .\gsc-synthetic-pages.csv --chart .\gsc-synthetic-dates.csv --chart-date-format mdy

Expected fictional result: 31 October dates, 62 property clicks and 3,100 property impressions from the sample chart, versus 22 clicks across the three sample Pages rows (12 Technology, 7 Poker, 3 Other). The gap is intentional: page-row totals cannot stand in for property totals. Optional query figures remain unavailable because no query file is supplied. These files are not genuine Google exports, Nolan Kido traffic measurements or evidence of SEO growth. This release of the checker recognizes nolankido.com URLs and its section names are specific to this site; using it for another website requires adapting those rules. The checker still prints its standard privacy warning because real exports must stay private.

Google explains the property-versus-page counting distinction and export row limits. The open-source tool's initial release, daily-chart validation and explicit date formats are inspectable changes, not observed search gains. The script prints aggregate JSON locally, writes no file on its own and never sends your CSV data away.

A method you can reuse: name a reader's question, identify the best existing page, make a useful and accurately linked revision, preserve its canonical URL, verify the published result, and measure the outcome separately. Google's link guidance explains crawlable descriptive links; its sitemap guidance explains when a changed date is meaningful. Neither promises a ranking increase.

How to measure AI-search citations without treating them as search clicks

A site can appear in an AI-generated answer without receiving a visit, and a cited page is not necessarily a high-ranking ordinary search result. Four separate measurements help keep the claim honest. Download a blank monthly AI-search observation worksheet, or read the complete public measurement protocol. Keep completed records private.

A repeatable no-cost monthly check

  1. Fix the scope first. Use the last complete calendar month, note the search property and filters, and keep a fixed panel of unbranded practical questions. Do not replace the panel each month with prompts designed to produce a favorable response.
  2. Read the first-party reports separately. Record Google Web clicks, the dedicated Google generative AI Search impression view when available, and Bing's AI Performance citations. The AI-impression view overlaps with overall Google Search performance. Preserve each provider's date range and coverage; do not add these figures together.
  3. Check traffic separately. Look for recognized assistant referral domains or campaign parameters in your own analytics, if available. Missing referrer data cannot prove that no AI-assisted visits occurred.
  4. Sample actual answers. Run each fixed prompt in a new search-enabled conversation, record the product and mode, and count a trial as cited only when the completed answer includes a genuine clickable link to the domain. A text-only mention, search snippet, or URL you supplied in the prompt is not a verified citation. Count each completed trial at most once.
  5. Compare without inventing causality. Save exact dates, completed-trial denominators, and the original page URLs privately. A before-and-after change could reflect demand, search systems, competitors or sampling variation, not only your latest article.

Fictional interpretation: If two of 16 completed answer trials contain a clickable domain link, the observed sample fraction is 2/16, or 12.5%. It is not a platform-wide citation rate. Seven reported Bing citations would remain a separate provider metric, and a missing Google AI report would be recorded as unavailable, not zero.
