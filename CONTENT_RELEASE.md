# Personal-home content revision

This revision keeps the approved editorial visual design while improving the site's usefulness, readability, and invitation to conversation. `styles.css`, `assets/site.css`, `assets/contact.js`, the favicon, and the domain configuration are preserved.

## Public changes

The introduction is now “I build useful things and write about what I learn.” The numerical status strip is removed. A worked explanation provides the main reading entry point; a separate small selection makes room for communication and life beyond work. The About, Bio, Card, Contact, Notes, Resources, and page metadata use the same public identity.

The three existing essays retain their URLs but now include worked examples and clearer boundaries. Two additional general essays discuss generous explanations and finishing work. They are not presented as autobiographical accounts. Examples are labelled fictional and the articles retain AI-assistance disclosures. The learning essay links the primary retrieval-practice study and limits the interpretation to the setting studied.

Each resource provides intended-use guidance, reasons not to use it, a completed fictional example, a preview of the blank copy, and a private-use download. No answers are collected. Topic and context on the contact form are optional; the existing request-handling and anti-spam code is unchanged.

## Maintenance

The public content manifest supports explicit publication and update dates, visible revision notes, and corresponding machine-readable metadata. A separate selection file controls curated links and reading order without manipulating publication dates. The editorial guide sets boundaries for future writing, factual checks, owner approval, and a small manual review practice. It does not schedule any background task or claim that domain/account settings have been changed.

## Verification scope

Run the structural/design/content tests, mocked contact tests, and real-page browser checks documented in README. These cover links, fragments, feeds, metadata, deterministic output, illustrative arithmetic, resource downloads, narrow layouts, and preserved visual/form code. Provider account configuration and actual message delivery require a separately authorized live submission and inbox check; neither is implied by mocked success.
