# Turn 52: make Nolan's profile and biography findable

Reviewed November 5, 2026, Pacific time. Baseline: verified Turn 51 receipt `a4745e5882d72f9a3492a1b257eeee9e7dafae4e`.

## Reader problem and result

The site's own Find page excluded About and Bio. A reader could search Nolan's name and receive many articles without finding the two pages intended to introduce him. Browser checks against the committed baseline reproduced the problem and the corrected behavior:

| Search | Before this change | After this change |
| --- | --- | --- |
| `Nolan Kido` | 162 matches, with neither About nor Bio | About Nolan Kido is the first result; both personal pages are included |
| `who is Nolan Kido` | 14 matches, with neither About nor Bio | About Nolan Kido is the first result |
| `biography` | No results | The existing biography is the sole result |
| `short bio` | Not included in the baseline browser sample | The existing biography is the sole result |
| `Nolan Kido biography` | Not included in the baseline browser sample | The existing biography is the sole result |

The baseline browser used the exact Find HTML and search script from the baseline commit. It included the existing section-heading matches, rather than estimating behavior from page titles alone.

Name searches still have broad matches because many public article titles contain Nolan's name. The improvement puts the two relevant introduction pages in a clear **About Nolan** group before the topical groups. It does not claim that every matching article is relevant to every name query.

## Implementation

- The existing index generator includes only the two already public identity pages, reusing their exact manifest title, search title and description.
- The new **About Nolan** area appears first. Technology, Living Well, Poker and Creative Work retain their existing order and memberships.
- The **About & biography** page-type filter is separate from the existing **Player profiles** filter.
- The existing search logic treats `who` like its other question words. A query containing only question words still produces no results.
- Search instructions, placeholder text and the Find description now make the personal pages discoverable. Results and controls use the same area terminology.
- Both pages remain ordinary HTML links, accessible from the first browse group without JavaScript or when the search script is blocked.
- Enlarged-text testing found a six-pixel navigation overflow at a 320-pixel viewport. A Find-only CSS rule allows those navigation links to wrap.

No new biography, credential, professional title or personal claim was authored. The original About and Bio outputs remain byte-identical. Neither identity result receives an article publication date. Contact, Privacy, the contact card, unpublished plans and other excluded material remain outside this index.

Search still filters the public HTML already on the page. Browser checks observed no query-triggered network request, no saved query in local or session storage, no cookies and no query in the page address. The query clears when returning from an opened result.

## Scope and preservation

Only three public resources change: `/find/`, `/assets/site-find.js` and `/assets/site-find.css`. The main generator produces one changed HTML page. The public search inventory grows from 187 to 189 entries, without creating a new page URL.

All article pages, article dates, feeds, the sitemap, About and Bio remain byte-identical to the baseline. Find retains its existing `noindex` treatment and remains outside the sitemap. This release improves navigation within the site; external indexing, rankings, AI citations and visitor satisfaction were not measured.

The Find source revision is November 5 in the owner's current Pacific time context. Earlier published records retain their existing dates.
