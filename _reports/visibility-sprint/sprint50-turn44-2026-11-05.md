# Turn 44: validate full-month Search Console chart totals offline

Reviewed November 5, 2026. Starting `main` commit: `86560346d7fa25b58ea752aad80c550e2aff57da`.

## Why this turn

The preceding [Turn 43](sprint50-turn43-2026-11-05.md) released a no-cost, offline CSV tool for observed page and query performance. It intentionally left property-wide Web clicks and impressions `null`, because summing exported page rows does not reproduce the Search Console property chart. The owner would still have to copy those two figures manually. A guarded daily-chart import can remove that transcription step without introducing a paid connector, private data collection or unsound query-to-page inference.

Google's [Search Console export documentation](https://support.google.com/webmasters/answer/12919797) explains that chart and table values can be exported together; table rows can be capped, and unavailable display values may become zeros in exports. The [Performance report help](https://support.google.com/webmasters/answer/7576553) identifies property clicks and impressions as chart measures. Those constraints shaped the change.

## What changed

1. `downloads/gsc-monthly-local-audit.py` now accepts an optional `--chart` CSV with `Date`, `Clicks` and `Impressions` headers. It accepts ISO `YYYY-MM-DD` dates only, requires one unique row for every actual calendar day in the declared month, and rejects duplicate, invalid, missing or out-of-month dates. Leap years use the calendar, not a fixed 28/30/31-day approximation.
2. Only a complete daily chart is allowed to populate `property_web_clicks` and `property_web_impressions`. Page-table sums are still strictly observed-row section measurements, not substitutes for property totals. Without a chart, both property figures still return `null`.
3. `chart_export` explicitly records whether a chart was provided, whether calendar coverage was checked, and the number of daily rows. `export_date_range_verified` remains `false`, because the tool cannot prove that the owner's Pages and Queries files came from the same selected date range, property or Search type, or that Google's latest data was settled.
4. The existing [public measurement protocol](seo-geo-measurement-v1.md#offline-local-csv-summary) now includes an optional Chart CSV in the Windows PowerShell example, the rules for ISO dates and manual cross-checks, and Google's caution about exported zeros and table limits.
5. The [Technology visibility case](https://nolankido.com/technology/#site-visibility-limits) now accurately describes optional full-month chart totals alongside the existing privacy and evidence limitations. The authored source and generated public page contain the same bounded statement. Canonical URL, source identity, publication dates and unrelated site copy remain unchanged.

## Private usage

From the repository root after privately exporting October 2026 Web Search results:

```powershell
py -3 downloads/gsc-monthly-local-audit.py --month 2026-10 --pages "$env:USERPROFILE\Downloads\Pages.csv" --queries "$env:USERPROFILE\Downloads\Queries.csv" --chart "$env:USERPROFILE\Downloads\Chart.csv" > "$env:USERPROFILE\Documents\gsc-2026-10-private.json"
```

All filenames are illustrative. Inputs and output must remain private. The script has no network client, scheduling or automatic file output. The PowerShell redirection above, when a user chooses to run it, saves the JSON in the user's own Documents folder. The measured figures in this release come exclusively from synthetic tests, not owner analytics.

## Limits and next decision

A full set of day labels does **not** prove that Google finalized the data or that the files came from the correct verified property and filters. The owner must inspect those in Search Console, particularly for very recent dates. The tool is not an AI citation monitor and does not perform a genuine independent reader study. Use authenticated, settled first-party exports before making page-specific search-performance claims, and keep all such results out of this public repository.
