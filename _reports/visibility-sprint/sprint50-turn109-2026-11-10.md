# Turn 109: Shorten manual-copy guidance and expose it on focus

Date: November 10, 2026

Baseline: `f4c1d6c2d1205511298c428c5e3ff31ad61e83b9`

## Observed reader problem

The published Task Brief Builder's manual-selection cue wrapped to **206
pixels high** at a deliberately extreme **160 CSS-pixel-wide** browser
viewport. Its top was at **402 pixels** and the selected text field did not
start until **620 pixels** in a 700-pixel-high window. This narrow-width
stress test is **not** a measurement of native 200% browser text scaling.

The cue also appeared visually when the complete textarea was selected,
but the textarea's accessible description still named only the generic
brief explanation. A reader entering the textarea with assistive
technology could miss the immediate, important distinction between
**selected** and **copied**.

## Improvement

- Shorten the adjacent visible instruction to **"Selected, not copied.
  Use your device’s Copy command."** Its meaning and truthfulness remain
  unchanged, with fewer words consuming vertical space on small screens.
- While manual selection is active, expose that instruction as the
  **first** `aria-describedby` target for the read-only textarea. Set
  the description before moving keyboard focus to the selection.
- When selection is superseded by a successful copy, a new
  print/download attempt, a rebuild, an edit, or a clear, restore the
  textarea's original description so hidden guidance is not read later.
- Preserve the full selected text, the first-line scroll reset, the
  visible status, the sticky-header clearance, and all privacy boundaries.
- Add two local regressions that exercise production handlers and assert
  the accessibility description **at focus time**. Retain the previous
  visible-cue regressions with the shorter text.
