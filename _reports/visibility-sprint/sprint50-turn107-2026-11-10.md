# Turn 107: Keep Task Brief export feedback truthful

Date: November 10, 2026

Baseline: `35b19157d474c16d6221e65f5a139b9e9adc2e22`

## Observed reader problem

The Task Brief Builder offers Copy, Save as text, Print and Select text
manually. Browser clipboard writes are asynchronous. A person could start
**Copy brief** and choose another export action before the clipboard request
resolved. The earlier clipboard promise could then replace the latest
action's status or select the textarea after a later action, obscuring which
operation needed attention.

The old feedback did not consistently distinguish text that was selected
from text that was placed on the clipboard. Download and print requests
were intentionally not completion receipts, but their follow-up
instructions could better direct the reader to check the browser.

## Improvement

- Treat every export action as the latest one. Older clipboard promises are
  ignored if a newer Copy, Select, Print, Download, rebuild, edit or clear
  action occurred. This prevents an old rejection from stealing focus and
  an old success from replacing a newer status message.
- An in-flight browser clipboard write cannot be canceled by this page.
  The guard protects what the page claims and which control receives focus;
  it does not guarantee that the system clipboard was unchanged.
- Say **copied to the clipboard** only after the browser reports clipboard
  success for the current brief and action. In manual selection and failure
  states, explicitly say that selected text is **not copied**.
- Describe downloads and print dialogs as **requested**, and tell readers
  to verify the browser outcome. Do not claim that a saved file or printed
  page has been confirmed.
- Clarify the on-page export help before the buttons. Preserve the accessible
  live status region, locally assembled content, source dates, and the
  previously verified first-line selection and mobile header clearance.
- Add three focused regression tests, including a Node-driven execution of
  the actual handlers with deferred clipboard success and rejection, changed
  input, reassembly, export fallbacks and requested-only print/download
  outcomes. Register the tests in the manual release checklist.
