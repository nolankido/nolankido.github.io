# Turn 47: align the homepage's last significant content revision with search metadata

Reviewed November 5, 2026. Starting `main` commit: `15f7cc383ffadad76f9fc9d36091923a54a957f7`.

## Why this turn

The canonical homepage gained a substantive source-linked evidence section in [Turn 38, PR #194](https://github.com/nolankido/nolankido.github.io/pull/194), and its first-screen navigation was revised in [Turn 39, PR #195](https://github.com/nolankido/nolankido.github.io/pull/195). Both changes merged on November 5, 2026. Yet the site's source manifest still declared `"updated": "2026-11-03"` for the homepage. The generated `index.html` structured data reported the same older `dateModified`, and the main sitemap reported `<lastmod>2026-11-03</lastmod>` for `https://nolankido.com/`.

Google's [Search Central sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap) describes `lastmod` as a signal for the last significant page update, including changes to main content or links. The November 5 evidence section and its navigation shortcut meet that description. This correction addresses an actual timestamp inconsistency. It is not an artificial freshness update, and it is not evidence that Google will recrawl, index or rank the page differently.

## What changed

1. `_source/pages.json` now records the homepage's last substantive change on November 5. Only the `home` object's `updated` field changes.
2. The generated `index.html` changes only the WebPage schema `dateModified` from November 3 to November 5. Its visible content, title, canonical, Person identity, publisher, links and social metadata remain exactly as before.
3. `sitemap.xml` changes only the `lastmod` of `https://nolankido.com/` to November 5. Other sitemap dates and all existing URLs remain unchanged.
4. `_tests/test_turn47_home_freshness.py` requires the manifest, homepage structured data and sitemap to agree on a date no earlier than the documented evidence revision. It also keeps the actual source-linked evidence and all three Person IDs recognizable. Deliberately stale and corrupted fixtures exercise failure paths.
5. `_scripts/local_release_checks.py` now runs the homepage freshness suite in its ordinary local checklist. This is not a network, recurring, paid or CI job.

No new page, image, script, consent flow, analytics export, address, credential, professional claim, poker outcome, AI citation claim, GitHub Actions workflow or cron job is introduced. All article publication dates remain unchanged.

## Interpretation and next evidence

A trustworthy site should distinguish when its pages actually changed from when a bot or editor merely touched a file. This release corrects an identifiable mismatch after an independently visible substantive homepage revision. Google's use of `lastmod` is conditional on signal reliability, and a sitemap is a crawling hint, not a ranking guarantee.

The more consequential unresolved work remains an owner-approved, rights-cleared portrait and verified professional timeline, independent outside-reader comprehension checks, and actual owner-controlled Search Console/analytics measurements. These need their own evidence and permission. Do not create a new date simply because a future check ran.
