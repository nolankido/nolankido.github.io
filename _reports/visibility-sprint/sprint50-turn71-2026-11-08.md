# Turn 71: Make optional historical tests observable and repair a frozen inventory check

Date: November 8, 2026

Baseline: `8da7ea2225b2c9149f9d525f3d16c7bbac5d46c6`

## Problem verified

The local default release gate was green after Turn 70, but its optional
`--full` mode ran all 226 historical unit modules in a single process. An
exploratory full run could be interrupted without a trustworthy partial
pass/fail count. The archived tests also contain expectations tied to
superseded public releases, including file-inventory totals and specific
historical output bytes.

## Changes

1. Added `_scripts/check_historical_batches.py`, a local-only diagnostic runner.
   It selects test modules in a stable order and runs each in its own process,
   with a configurable hard per-module timeout, per-file result, test count,
   and finite failure excerpt. Zero-test and malformed successful exits do
   not count as passes. An optional JSON checkpoint is written after each
   module; if interrupted, unrun modules remain explicitly unrun.
2. `python _scripts/local_release_checks.py --full` now uses that runner with
   `--all` and a 90-second timeout per module. The ordinary default checklist
   is unchanged. No GitHub Actions, cron, CI service, scheduled job, paid API
   or network service was added or invoked by these checks.
3. Added `_tests/test_historical_batch_runner.py` to test discovery,
   timeout treatment, empty tests, failure reporting, checkpoint writing,
   bounded selection, bounded console output and `--full` integration.
4. Repaired `_tests/test_best_five_history.py` to read the one superseded
   Poker library page from the exact reviewed best-five release instead of
   today's newer page. The archived blob is checked by its Git SHA, and the
   existing SHA-256 release ledger remains enforced.
5. The production-inventory fingerprint regression now reads the exact
   parent Git tree (`501990c1079b89738aa19d9c48def5f1346bc09d`) of the
   best-five release (`2809bbf4a234331ab6413323f3d100ccc823bd0f`).
   That original tree has exactly 714 production files and reproduces the
   ledger's SHA-256 fingerprint
   `47f8614f5582d872bba8f3a0e858e8084c2deccc795bcf4d22c28cce8e1d94f8`.
   The intentionally deleted GitHub Actions workflow is inspected only from
   the archived Git commit; a new regression confirms it remains absent from
   the active worktree. No predecessor adapters or historical ledger data
   were changed.

- The best-five archival module now has **five passing tests**, versus two
  failing assertions among four tests beforehand.
- A real, bounded sample of the first eight of 36 `test_*history*.py` modules
  completed in approximately 15 seconds: **one PASS, seven FAIL, zero TIMEOUT,
  zero ERROR**, with 52 completed test methods observed. The seven failures
  remain visible and are not treated as release passes. The other 28 matching
  history modules were not sampled in this invocation.
- The **default local release checklist passed 34 of 34 groups**, including

  links and 4,024 fragments without issues, 202 search/sitemap URLs without
  metadata errors, and HTML5 parsing of 207 pages. Python compilation and

- Browser suites were not run; the entire optional historical test suite was
  not run. No all-green historical-suite claim is made.
