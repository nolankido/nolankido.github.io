# Turn 147: Complete the sideways-reading cues across Technology evidence tables

Date: November 12, 2026

Baseline: `5c4228c855267c78f946d2c3d84f1db7de346e04`

## Observed problem

Turns 144 and 146 added visible horizontal-reading instructions to the
Preflight, Review Reply Writer and Technology landing-page tables. An audit
of the remaining Technology source found **12 additional wide evidence
tables across seven articles**. Each used the same minimum-width table
style and focusable scrolling region, but none explained that phone readers
could swipe sideways or that keyboard readers could use the arrow keys.

The absence of an affordance is inspectable in the source. No visitor
study or usage logs were used to claim that readers actually missed the
hidden columns.

## Improvement

- Add a short visible touch-and-keyboard instruction immediately before
  all 12 remaining Technology tables on the poker-video evidence,
  local-AI gaming-laptop, website-visibility, organized-notes,
  AI-answer-checking, local-model test-record, and independent reply-audit
  articles.
- Give each instruction a unique ID and connect its named, focusable
  table region using `aria-describedby`. Keep table captions, evidence
  rows, facts, source links and calculations unchanged.
- Extend the existing shared stylesheet with a rule scoped to those
  seven Technology article body classes. Hide the screen-only instructions
  in print, where the existing print rule removes table minimum width.
- Add four local regression tests with deliberate negative controls.
  They verify each new article and the complete inventory of **18
  Technology table regions**, including the previously improved pages.
- Narrow the older Turn 146 CSS negative assertion to reject genuinely
  unscoped rules while permitting other page-scoped guidance. Register
  the new tests in the local release checklist.
- Rebuild the main site and refresh both separately owned local-AI
  articles to carry the new content-derived CSS version. Preserve all
  canonical URLs, article and sitemap dates, historical claims and
  existing scope limitations. No new JavaScript, data collection,
  paid service, CI, GitHub Actions or automation.

## Evidence boundary

in the observed browser states. It does not establish that readership,
comprehension, accessibility for every user, search rankings, AI

firsthand poker claims and caveats have not been modified.
