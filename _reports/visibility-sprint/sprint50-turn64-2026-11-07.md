# Turn 64: Make Nolan Kido's AI task brief readable with enlarged text

Date: November 7, 2026

Baseline: `7284bb78178406a182587a749095abea4ba56310`

## Observed problem

The `/technology/task-brief/` page demonstrates a small, local, privacy-conscious AI workflow: a person defines a goal, boundaries and a check before deciding whether to use another service. This practical example connects Nolan Kido's name to his stated approach, **AI Works, Human Decides**. Its professional presentation matters even when a reader enlarges text.

An offline Chromium rendering at a 320-pixel viewport, 200% root font size and additional letter, word and line spacing found two distinct problems:

- The shared three-column mobile navigation made **Technology**, **Living Well**, **Creative Work** and **Contact** collide with neighboring navigation items. This was not evident from the normal-font presentation.
- The page widened to **413 pixels**. The long heading **A few useful constraints.** contributed a 393-pixel scroll width inside its 280-pixel content region. This forced horizontal scrolling on a narrow screen.

The same setup also found that section fragments could settle roughly 180 pixels from the top of the viewport while the enlarged sticky header extended to about 316 pixels. That put the target beneath the header. These are measured local layout states, not visitor statistics.

## Focused improvement

- Give this page's `.section-content` an anywhere-wrap fallback for enlarged headings and long example text.
- On viewports of 620 pixels or less, replace the cramped three-column navigation with a wrapping, naturally sized row. Keep all six existing links, their order and their destinations. Let the NK brand mark grow with reader text.
- Give the existing native section targets a mobile scroll margin that combines with the site's existing scroll padding. Keyboard fragment navigation then leaves headings visible below the enlarged sticky header, with no new scroll-handling JavaScript.
- Add `_tests/task_brief_reader_browser.py`, an offline Chromium regression. It covers both script-disabled reading and the existing local builder script running with enlarged text.

All styling changes live in **`assets/task-brief.css`**. No shared stylesheet, article text, metadata, identity schema, original task examples, JS builder logic, source date, sitemap or feed changed. The deterministic builder updates only the stylesheet's content-hash reference in `technology/task-brief/index.html`.
