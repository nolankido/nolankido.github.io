# Turn 69: Make the local release gate distinguish history from current behavior

Date: November 8, 2026

Baseline: `be7f099e19c463c8fdc51c9cb6047e2bfd2bab2a`

## Problem reproduced

The default local release checklist was stuck at **26 of 34 groups passing** after Turn 68. Eight Turn 35 through Turn 42 test groups failed even though their current site-content and safety contracts were passing. A focused audit identified **13 historical test methods** that required current files to match old whole-file releases. Later approved site improvements necessarily changed those files, so the archival checks produced misleading release failures.

Some old tests also reversed an original homepage insertion directly from today's full homepage, which contains many later reviewed changes. The historical predecessor adapters deliberately fail closed on unknown future bytes, so widening those adapters until the old assertions passed would have weakened the safeguards.

## Improvement

Added `_tests/reviewed_release.py`, a test-only reader for explicitly pinned full Git commit IDs and repository-relative paths. It verifies each retrieved file's Git blob SHA-1 against its **unchanged original change ledger**. It rejects mutable branch names, malformed hashes, out-of-repository paths and content that differs from the recorded blob.

Corrected historical assertions in the eight existing test groups:

- Turn 35's new AI-and-poker article, old predecessors and live response are checked against the original reviewed release.
- Turn 36's About navigation, responsive CSS and predecessor records are checked at their original release.
- Turn 37's added link-check files, registered probe download and predecessor records are checked at its original release.
- Turns 38 and 39 check that their original homepage additions were the only changes **at those releases**, without requiring all later homepage edits to disappear.
- Turns 40 and 41 check reviewed poker video and channel-route predecessors at pinned releases, without incorrectly requiring newly changed worktree bytes to rewind.
- Turn 42 checks the originally reviewed website case predecessors at a pinned release, while an added loader regression verifies that wrong hashes, mutable references and unsafe paths fail closed.

The original predecessor adapters and all historical JSON ledger hashes remain unchanged. Existing current-content contracts still read today's generated pages and sources. Existing negative controls still verify that altered bytes, unknown paths, invalid live response status and broken reader links are not silently accepted. No historical group was removed or skipped.

## Local verification

- **All eight formerly failing groups now pass**: 64 tests total, including the new pinned-fixture negative test. Prior targeted scope had 63 tests.
- **Default local release checklist: 34 of 34 groups pass**, an improvement from 26 of 34 at baseline.
- **231 deterministic generated site files** match their committed output with zero drift. Standalone player profile, poker episodes, local AI laptop guide and independent reply audit all pass exact-source build checks.
- The local link scan covers **13,984 internal links**, including **4,024 fragments**, with zero issues.
- Search checks cover **202 sitemap URLs** with unique titles and descriptions and no errors. HTML5 parsing covers **207 pages** with zero errors.
- The standard release-integrity regressions pass, including guards against missing tests and a failing companion build being reported as green.
- Python compilation of the changed test modules and `git diff --check` pass.

Reproduce the main gate locally from a Git checkout with the original commit history available:

```sh
python -m pip install -r requirements-test.txt
python _scripts/local_release_checks.py
```

The optional `--full` historical unit sweep and optional browser suites were **not run as part of this turn**. The eight fixed groups are included in the default release checklist, but a green default result must not be described as evidence that every optional historic or browser test passes.

This is a **test-reliability improvement**, not a content, SEO ranking, accessibility or traffic result. No public page, source article, style, script, sitemap, feed, title, published identity or review date was changed. No GitHub Actions, cron, paid API or new CI system was added or invoked.
