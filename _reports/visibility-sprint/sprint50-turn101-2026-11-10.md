# Turn 101: Make the first AI task brief easier to start

Date: November 10, 2026

Baseline: `e2b2aa7ba0241900c110c0802f69e36f70251dba`

## Reader problem

The free AI task-brief builder on `/technology/task-brief/` opens with five
empty fields. Six useful fictional examples already follow the editor, with
buttons that fill those fields, but a first-time visitor has to find one
below the form before seeing a complete working starting point. This is an
observed source-layout friction, not a measured visitor drop-off.

## Improvement

- Placed a prominent "Load the editable meeting example" shortcut above the
  first field. The example is explicitly fictional and remains editable.
- Reused the same meeting record and safe loading code as the existing six
  example buttons. No duplicate, seventh example was introduced.
- Preserved the existing confirmation before replacing nonempty fields,
  cancellation returning focus to the initiating button, and goal-field
  focus after successful loading. Example content is validated before loading.
- Revised the optional native walkthrough to mention both entry paths.
- Kept the shortcut inside the progressively revealed editor, with the
  original static examples and blank template available without JavaScript.
  The shortcut is hidden from print layouts.
- Refreshed the actual Task Brief content date and Find description. Other
  pages' publication dates and the established example text stay intact.
- Added four focused tests, including synthetic DOM clicks for initial load,
  cancel, confirm, original example reuse, and an invalid-record guard, and
  registered them in the manual local release checklist.
