# Turn 122: Keep manual Copy guidance accurate after focus leaves

Date: November 11, 2026

Baseline: `e77cb0e166cf44a618e214fabe2cee9f8db5fdb9`

## Reproduced live problem

On the published AI Task Brief page, I loaded the fictional meeting example,
assembled the brief, and activated **Select text manually** using a connected
Chrome browser. The textarea was focused and contained a genuine full-range
selection: start `0`, end `1454`, text length `1454`. The nearby cue correctly
read **Selected, not copied**.

I then pressed **Tab** from the textarea. Keyboard focus moved to a `SUMMARY`
control, while the textarea retained its start and end range. The nearby cue
still read **Selected, not copied**, incorrectly suggesting that the next
keyboard Copy command would necessarily target the text box. This was a
reproduced live browser behavior, not an inferred or synthetic-only issue.
The temporary browser test tab was closed.

## Improvement

- When the text box loses focus during the manual-copy handoff, change the
  visible cue and the nearby fallback group's accessible title to **Text box
  no longer focused**. Instruct the reader to choose **Select text manually**
  again before copying. Update the accessible live status too.
- Ignore late text-selection events from a textarea that is no longer focused,
  even when its stored selection range still spans the full brief.
- When focus returns, check the actual range again. Restore the selected-but-
  not-copied guidance only if the full range is still selected. Otherwise
  request renewed full selection.
- Preserve a previously observed native **Copy** command message, including
  the explicit warning when only part of the brief was selected. A native
  Copy event remains an observation, not proof of clipboard contents.
- Test full selection, Tab-away, retained range, focus return, partial range,
  manual reselection, native Copy detection, and field-edit invalidation with
  a deterministic Node-driven browser-event simulator. Register this test in
  the existing manually run release checklist.

No changes to assembled text content, field data, third-party services,
permissions, tracking, storage, network calls, article revision dates, or
GitHub Actions were introduced. Existing Save and Print fallbacks remain.
