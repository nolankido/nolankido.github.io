# Turn 72: Restore the original brand and profile history boundaries

Date: November 8, 2026

Baseline: `c6fdd17001523a9aa29852356736ba4fd8fbedee`

## Observed failures

Turn 71 made the optional historical test sweep measurable in small batches.
The first eight `test_*history*.py` modules contained seven failing groups.
Two were the brand release's predecessor and composition tests:

- `_tests/test_brand_history_composition.py` ran five tests with five failing
  assertions. Its metadata input came from the current, much newer site
  manifest, so an October 2026 brand reversal did not match the recorded
  full-record boundary.
- `_tests/test_brand_positioning_history.py` ran four tests with three failing
  assertions. It expected old metadata and generated HTML from today's site,
  even though later changes correctly altered the page descriptions and linked
  to public historical identity files. It also assumed an unrelated later
  conversion of `_scripts/practical_path.py` must leave bytes unchanged,
  although the conversion produced the recorded predecessor exactly.
- The test-only `_tests/turn10_profile_history.py` date adapter derived old
  About and Bio dates by reading today's `_source/pages.json`, potentially
  substituting 2026-11-06 for the independently recorded October 2026 dates.

## Improvement implemented

1. `_tests/turn10_profile_history.py` now reconstructs its historical dates
   from the existing compressed predecessor bytes in
   `_tests/turn10-profile-change.json`. It verifies the frozen SHA-256 before
   parsing and fails closed on corrupted encoding or digest. It no longer
   relies on today's public page manifest for a historic date.
2. `_tests/test_brand_history_composition.py` takes the complete brand-release
   manifest from pinned Git commit
   `1a62b90dd278b82a2716a429b1265b6dea5ab203`, verified against blob
   `4ac979a431290dbb4838de3fc370b2ed4b74a416` and the existing brand
   release SHA-256 ledger. Its tests now compare the intended old/new metadata
   records and verify the older About and Bio dates independently from later
   site revisions. Added an explicit corrupt-digest rejection test.
3. `_tests/test_brand_positioning_history.py` reads five exact brand-release
   blobs from the same pinned Git commit, including the page manifest, the
   practical-path helper and three entry pages. The historic entry-page
   assertions apply to those original bytes, not to today's intentionally
   changed case-study content. Today's rendered pages are still checked for
   the brand phrase and absence of the former headshot filename.
4. The practical-path history test now accepts a later independently reviewed
   reversal **only if** its result matches the original predecessor SHA-256.
   New negative controls ensure altered archived brand bytes remain visible
   rather than being normalized away. No history adapter or golden hash was
   modified to conceal a mismatch, apart from the date-source correction
   described above.
