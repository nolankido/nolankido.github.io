# Turn 146: Reveal horizontal evidence columns on the Technology hub

Date: November 12, 2026

Baseline: `0e81bc77d3cf83c29448b2668a3e6f0feaf7ec6c`

## Observed problem

The main `/technology/` landing page contains three evidence tables:
the identity-claim correction, the poker-video fact boundary, and the
constructed scene-check examples. Each table's existing shared style
sets `min-width: 38rem` and gives its region horizontal overflow and
keyboard focus. On a phone-width viewport, later columns are therefore
outside the initial visible region. Before this turn the landing page
gave no visible swipe or keyboard instruction for those tables.

This is an inspectable navigation and accessibility affordance gap.
It does not establish that visitors failed to see the columns.

## Improvement

- Place a short instruction immediately above each of the three tables.
  Tell phone readers to swipe sideways and keyboard readers to focus the
  region and use the horizontal arrow keys.
- Give the instructions unique IDs, and connect each existing named,
  focusable region with `aria-describedby`. Preserve the table captions,
  header cells, evidence links, rows and values.
- Style the guidance only on `.page-technology` in the stylesheet already
  loaded by that page. Hide the screen-specific instructions in print,
  where the existing table styles drop their minimum width.
- Regenerate source-owned public HTML and every stylesheet hash consumer.
  Refresh the two independent AI case builders after the main build so
  that the new asset version agrees across all pages.
- Add four dependency-free regression tests with negative controls and
  register the group in the local release checklist. No new JavaScript,
  remote service, tracking, GitHub Actions or deployment workflow.
- Preserve the public URL, 2026-11-06 content revision field, structured
  identity, factual claims and recorded study limitations.
