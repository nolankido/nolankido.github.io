# Turn 115: Keep export alternatives beside the selected brief

Date: November 10, 2026

Baseline: `29ee36b6feb7546c62e633a078a8e3fcf393fc58`

## Reader problem

When an automatic clipboard write was unavailable, the Task Brief
Builder selected the complete plain text and moved the viewport to the
selection. The other export actions remained above it. A visitor with
blocked clipboard access, unreliable keyboard commands, or difficulty
scrolling back could miss the independent text-download and print/PDF
routes at the moment they were most useful.

## Improvement

- Introduce a hidden-by-default, labeled group immediately between the
  manual-copy cue and the plain-text brief. It appears only when the
  visitor selects text manually or an export fallback selects it.
- Put **Save full brief as .txt** and **Print / Save as PDF** buttons
  beside the selected text. Both call the existing export procedures
  directly from the visitor's button activation and use the entire
  assembled brief, irrespective of the current text selection.
- Explain in the main export introduction that clipboard, text file and
  print/PDF are independent choices.
- If a download or print call throws, hide the failing action within
  the contextual group while offering the other one. Reset both choices
  the next time the group opens for ordinary manual selection.
- Hide the temporary group on a successful export request, a new copy
  attempt, field editing, a rebuild, clearing, or page navigation.
- Preserve accurate outcomes: clipboard success is reported only after
  the browser confirms a write; local file and print operations are
  **requested**, never claimed as verified saves. The visitor is asked
  to confirm the result personally.
- Add a dedicated Turn 115 regression for functional events, fallback
  visibility, failure transitions, complete exported content, reset,
  accessible markup, asset versioning and local-only operation.
