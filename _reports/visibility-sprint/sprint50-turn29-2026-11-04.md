# Visibility sprint Turn 29: Reproducible notes-to-action AI case

Reviewed: November 4, 2026. Starting `main` commit: `061324dc666d4a5be9b1c0d63b1f11305cbb96f6`.

## Why this turn

The three-goal [public identity strategy](../identity-visibility-strategy-2026-11-04.md) calls for a second, distinctive real-world AI case that is not another website SEO or identity-data cleanup. A relevant genuine record already existed at `/technology/organize-public-notes/`: on October 27, an AI assistant converted eight public publication-preparation notes into eleven traceable checklist tasks, leaving unavailable personal reports blocked. The entire input, prompt and response were saved, and the page already explained that the checking stage found no substantive correction.

Rather than inventing a personal weekly reset, completed customer deployment, or fictional before/after failure, this turn makes that **existing genuine everyday note-organization workflow reproducible** and adds a separate deterministic, inspectable source trace. This is a substantive improvement to an established case, not a claim to have performed a new household experiment.

## What was implemented

- Expanded `_source/technology/organize-public-notes.html` and its generated `technology/organize-public-notes/index.html` with a source-trace case section, a four-row table of *constructed* negative controls, user commands, and an explicit human approval boundary. Kept the original task narrative and unedited input/output.
- Added `downloads/source-notes-audit.py`, a standalone standard-library checker. `--check public-notes-action-record.txt` reads the original Markdown output after the archived boundary and extracts its eleven tasks. It compares the expected note IDs, three status classes, and a small set of material constraints; it also catches unsupported absolute action dates. It does not read private notes, write files, call a model, or access the network.
- Added `--self-test` containing **five constructed** comparisons: one valid control and four altered cases involving invented readiness, wrong source ID, removal of the runtime-AI disclaimer, and an invented deadline. These are not errors observed in the original AI-generated response.
- Added focused Python tests in `_tests/test_turn29_source_notes_audit.py` and historical predecessor tests in `_tests/test_turn29_source_notes_history.py`. The tests are designed to invoke the checker on the archived eleven-row text, deliberate tampering, and a malformed input. They also verify source/generated HTML, dates, sitemap and local Find.
- Added test-only SHA-gated predecessor module `_tests/turn29_source_notes_history.py`. Updated the existing exact-blobs chains for the previous profile, Technology first screen, and prior fixed-baseline tests. Full unknown mutations remain visible and do not count as historical successors.
- Updated only the case's own `_source/pages.json` `updated` value, generated JSON-LD Article `dateModified`, Open Graph `article:modified_time`, sitemap `lastmod`, and one additional Find H2 entry. The October 27 **datePublished** remains unchanged.

## Recorded result, source limits and independent controls

The unchanged archive [public-notes-action-record.txt](../../downloads/public-notes-action-record.txt) identifies N1–N8 and reproduces the original assistant's output. The seven publication/editorial rows and four unavailable personal-report rows are not invented for this turn.

A source-to-output comparison read every archived task row and checked the expected source IDs, statuses and selected condition words. **All eleven passed the targeted checks; zero targeted flags were identified.** This is a check of consistency *with the supplied notes*, not independent verification that the notes were accurate. The earlier AI-assisted review had also found no substantive correction. Do not manufacture a failure simply to make the case more dramatic.

The new Python checker was executed locally with `--self-test` in an isolated environment on November 4, 2026. Its output indicated one passing synthetic control and the four expected negative-control flags:

| Constructed input change | Expected targeted flag |
| --- | --- |
| Travel plan status changed from blocked to ready | `STATUS_MISMATCH` |
| Travel plan evidence shifted N6 to N5 | `SOURCE_MISMATCH` |
| Dinner on Time disclaimer `no runtime AI` removed | `MISSING_BOUNDARY` |
| Unsupported outcomes assigned an invented `2026-12-01` date | `UNSUPPORTED_DATE` |

The actual output rows were separately checked against the rule matrix using the repository connector. The complete eleven-row GitHub file was not executed by Python in a local full repository checkout, because the connector-backed editing environment had no networked Git checkout. The new Python unit test will perform that exact check when executed from a complete checkout.

**Checker limitations:** a clean report does not mean original facts are true, a project was deployed, personal records were supplied, all possible hallucinations were caught, or all human consequences are acceptable. The rule matrix is intentionally specific to this published eleven-row example, not a general AI error detector, cybersecurity test or proof of time savings.
