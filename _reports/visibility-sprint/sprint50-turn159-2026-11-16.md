# Visibility sprint Turn 159: Run browser QA without a network origin

Date: November 16, 2026
Baseline main: `4d141d962271c5ab5af24015ace7d431c6ec227b`

## Why this turn

Turn 158 strengthened the native keyboard checks for three documented
NolanPoker hand exercises. Its offline Playwright suite routes fake
`https://nolankido.test` pages into committed local files.
In the current restricted browser environment, even routed requests for
that host and `http://127.0.0.1` fail immediately with
`net::ERR_BLOCKED_BY_ADMINISTRATOR`. The full suite cannot
reach its first document, despite the local files and Chromium being
available. This is a test-environment blocker, not proof of a broken
production website.

The existing live-site browser audit had already verified that all
three disclosures open by pointer and that the Continue links point
to the correct published study-guide sections. It could not inspect
all mobile widths. Repeatedly running the same fake-origin suite
does not resolve this gap.

## Implemented

Added `_tests/poker_hand_review_content_browser.py` as a
second, deliberately different browser-testing method. It uses the
existing committed standalone companion and study-guide HTML
and CSS without opening an HTTP or fake HTTPS URL.

1. Read each of the four committed generated pages directly from the
   checked-out repository.
2. Find only locally referenced `/assets/` CSS files,
   verify their paths stay inside the repository, and inline them in
   the existing document order. Fail if a required asset is absent.
3. Remove executable script elements and preloads and block all remaining
   asset requests. This tests the pages with JavaScript disabled and
   does not contact the production site, YouTube, analytics or any
   outside service.
4. Render the entire committed HTML page in Chromium with
   `page.set_content()` at 320, 390, 768 and 1440 pixels.
   Normalize scroll animation only, so scroll positions can be tested
   deterministically; otherwise retain the site's native styles.
5. For each of the three documented hands, jump to the hand review,
   verify that the disclosure is visible below the sticky header and
   the page has no horizontal overflow, then check native keyboard
   focus, Shift+Tab, Enter to open, Space to close, and Tab to the
   immediate Continue link. The summary outline, answer padding,
   link height and matching source-limited destination are checked.
6. Validate the actual local Continue URL against the expected one,
   independently render its corresponding **committed guide page**
   and verify the heading fragment arrives below the sticky header,
   also without horizontal document overflow.
7. Report separate counts for complete-page exercise layout,
   keyboard paths and local destination checks, plus blocked asset
   requests and successful network responses.

**Important distinction:** this in-memory method does **not** prove a
cross-document HTTP navigation occurred. It tests the real authored
href and the target's separately rendered page. The existing
`poker_hand_review_browser.py` remains available to test
true navigation on a normal local checkout whose Chromium runtime
permits intercepted fake-origin URLs.

Added `_tests/test_turn159_content_browser.py` to check
Python syntax, correct route and fragment ownership, presence of
local CSS assets, no new network navigation or service, and negative
controls for lost keyboard tests and accidental network enabling.
Registered that focused test in the existing manual
_scripts/local_release_checks.py default checklist.
The existing `--browser` flag automatically finds the new
`*_browser.py` script. No new GitHub Actions, scheduled
service, CI system, web server, or paid API was added.

## Verification actually completed

- The new Python browser script compiled successfully using
  `python -m py_compile`.
- A **synthetic local fixture smoke test** exercised the implementation
  under the available headless Chromium, using a representative
  sticky header, three hand review/Continue controls, two matching
  guide destinations, and inlined CSS. The test completed:
  - 12 of 12 rendered exercise and header/overflow checks;
  - 12 of 12 keyboard disclosure paths;
  - 12 of 12 separately rendered guide-destination checks;
  - zero successful network responses, at 320/390/768/1440 widths.
- In a deliberate negative smoke trial, a fixture guide with no
  heading scroll margin failed the 320-pixel sticky-header assertion.
  Reinstating the guide's representative scroll-margin rule allowed
  the smoke test to pass. This demonstrates the check is sensitive
  to a meaningful error. It is not a production-site bug report.
- The tested local Python file was 8,935 UTF-8 bytes, matching the
  file committed through the connected GitHub repository.
- GitHub-side static checks verify the three original companion
  URLs, study-guide anchor IDs, local CSS links and manual test
  registration. The production pages, their dates, facts, metadata,
  existing browser test, sitemap and feeds remain unchanged.

**Not accomplished:** the complete browser run using the *actual
full-site files* in one local working tree. Those bytes were
available through the connected repository but not mounted in the
sandbox, and the sandbox could not clone the repo. The passing
synthetic fixture must not be represented as a full-site test pass.
No real-phone, screen-reader or normal intercepted-URL click test
was completed this turn.

## How to run with a complete checkout

From the repository root with Python and Playwright/Chromium installed:

```sh
python -m unittest discover -s _tests -p 'test_turn159_content_browser.py' -v
python _tests/poker_hand_review_content_browser.py
python _tests/poker_hand_review_browser.py
python _scripts/local_release_checks.py --browser
```


The content-only browser test also permits setting
`POKER_BROWSER_ROOT` to a dedicated fixture root
and `CHROMIUM_PATH` to the installed Chromium executable.
The default root is the parent of the _tests folder.
Do not use the fixture-root override when claiming full-page production
verification.
