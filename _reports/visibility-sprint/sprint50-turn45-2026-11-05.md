# Turn 45: accept explicitly selected Search Console chart date formats

Reviewed November 5, 2026. Starting `main` commit: `f276e610d41f033238747c86c405dde289c9d558`.

## Why this turn

Turn 44 allowed a complete daily Search Console chart export to supply property-wide Web clicks and impressions without summing truncated Pages rows. It required dates in ISO `YYYY-MM-DD` notation. But owners can encounter slash-separated dates in exported or spreadsheet-saved CSVs. Silently guessing the locale from an ambiguous string risks moving days between months and inventing a false trend. Requiring manual conversion before a private, local audit also makes the tool harder to use on Windows.

This turn extends the tool with an **explicit date-format choice**, while retaining strict full-month coverage, the offline privacy boundary, and the distinction between observed exports and proven search results. Google's [official export guidance](https://support.google.com/webmasters/answer/12919797) and [Performance-report guidance](https://support.google.com/webmasters/answer/7576553) describe the direct chart and table export workflow; neither substitutes for inspecting the owner's actual CSV and selected filters.

## Changes

1. `downloads/gsc-monthly-local-audit.py` accepts `--chart-date-format iso` (default), `mdy` (month/day/year), or `dmy` (day/month/year), and rejects unknown modes or a non-default choice without a chart.
2. Slash-separated values allow one- or two-digit months and days and exactly four year digits. The tool never infers a locale from the first row, and ISO remains strict. It normalizes each parsed date before checking uniqueness and the declared calendar month. Therefore, even different spellings of the same date cannot evade duplicate detection.
3. The `chart_export.date_format` field records the chosen mode, or `null` when no chart was provided. Full daily coverage remains mandatory before property totals are emitted, including leap-year February.
4. `_reports/visibility-sprint/seo-geo-measurement-v1.md` now explains the date-format options, CSV filename variations such as `Dates.csv`, and a standalone Windows download route for owners without a repository clone. The existing `--queries` and `--chart` inputs remain optional.
5. `_tests/test_gsc_monthly_local_audit.py` adds four synthetic regression cases: an `mdy` month, a `dmy` leap year, wrong/mixed formats and normalized duplicates, and private CLI output with an explicit format.

## Private Windows use

For a daily chart with month-first dates such as `10/1/2026`:

```powershell
py -3 "$env:USERPROFILE\Downloads\gsc-monthly-local-audit.py" --month 2026-10 --pages "$env:USERPROFILE\Downloads\Pages.csv" --chart "$env:USERPROFILE\Downloads\Dates.csv" --chart-date-format mdy > "$env:USERPROFILE\Documents\gsc-2026-10-private.json"
```

This assumes the single script was downloaded from the public Technology page. When chart dates are day-first, replace `mdy` with `dmy`. Omit the format flag for ISO dates. Select the right mode from the actual file and double-check totals against the Search Console chart. Never commit the exported CSVs or resulting JSON.

## Interpretation and release gate

An explicit format and complete calendar are **input consistency checks**, not proof that Search Console selected the intended property, Web Search type, device/country filters, or fully settled date range. Some chart totals are known only by looking at the original private report. The change does not collect external data, generate a public scorecard, measure AI citations or establish organic traffic growth.

The main site HTML, canonical routes, visible copy, public identity metadata and original publication dates were not edited in this turn.
