The source and generated identity asset were previously read back as byte-identical and the current Person ID and publication DOI were preserved. The HTML case adds no unverifiable numeric performance metrics.

The standard-library checker tests selected structural facts:
- Exactly one WebSite, Person and ScholarlyArticle node on both sides.
- Shared identity, name, alternateName, identifier and external profile list are preserved.
- Research DOI and full scholarly publication record are unchanged.
- Sensitive `jobTitle`, `alumniOf`, `hasCredential`, `affiliation`, and `worksFor` fields are absent from the revised record.
- New person fields and description changes are surfaced for manual review.

In the local standalone Python test harness, five synthetically constructed scenarios passed the script's built-in self-test. A synthetic clean pair returned exit code 0; adding a forbidden field returned exit code 2. These are **script behavior tests**, not measured model accuracy, search outcomes or professional credential verification.

## Human judgment and evidence limits

This site's owner authorized the website improvement process, but the individual educational and employer claims were not independently human-verified in the editing session. The assistant applied a conservative claim-publication rule. Removal means insufficient support in this review, not proof that a credential is untrue. A paper archived by MIT does not independently verify an MIT research appointment. The historical COO self-description and outside profile ownership remain subject to stronger review if promoted.

The standalone identity JSON-LD file is not linked into the current Home or About HTML. Its correction improves accuracy of the available record; whether a crawler or assistant uses it is unknown. No ranking, traffic, AI citation, engagement, external endorsement, savings, or satisfaction change is established here.
