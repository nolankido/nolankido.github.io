# Visibility sprint Turn 158: Confirm keyboard focus and strengthen the hand-review browser audit

Date: November 16, 2026
Baseline main: `bf0febb65aa45b02cb98d60f19ddf1ecf6d8cf71`

## Reader goal

Complete a dependable browser-level review of the three documented poker
hand exercises on the Episode 1 and Stand Off written companions, including
the transition to their linked 6–10 and 10–20 BB study-guide sections.
Improve genuine keyboard navigation without changing any hand fact, strategic
claim, publication date, video URL or canonical identity.

## Observations and interpretation

A **read-only live-site browser audit** of both written companion pages
verified that the three native details/summary disclosures started closed,
opened after a pointer click and revealed the expected source-limited
explanations. It observed the three appropriate Continue destinations:
`#bridge-sb`, `#depths` and `#icm-call`. No horizontal overflow
was noticed at the tool's default desktop viewport.

The same audit reported no focus ring after one Tab keypress. However,
it did not establish that the keypress reached an exercise summary or
Continue link, and it could not fully test Enter/Space on those controls.
Therefore **focus invisibility was not confirmed as a reproducible site
defect**. Sticky-header overlap was also not measured. The live browser
could not resize to 320, 390, 768 or 1440 pixels, so it does not establish
mobile layout quality.

A separate local, isolated Chromium probe using the same focus selectors
tested 320, 390, 768 and 1440 pixel viewports with native
`details`/`summary` and a subsequent `a` element. It observed:

- Tab focused the summary and matched `:focus-visible`.
- The summary's control outline was solid, 3 pixels.
- A focused exercise container acquired the added 2-pixel focus-context
  outline.
- Enter opened the disclosure, Space closed it, and Tab reached the
  Continue link, which also had a visible outline.
- These observations are **isolated-component results**, not full-page
  responsive or screen-reader certification.

## Implemented improvement

1. **Scoped visual focus context.** In
   `assets/poker-hand-review.css`, added
   `.poker-hand-review-check:focus-within` to outline the active
   exercise. Added an explicit `:focus` fallback for summary controls
   and next-study links. The original `:focus-visible` styling remains
   intact. This makes the focus destination more conspicuous even when
   the input-modality heuristic or browser automation is uncertain.
2. **Versioned published asset.** Refreshed only the stylesheet query
   parameter on the two manually built public companion pages to match
   the new Git blob identity `101d8547374f`. The authored hand
   records and standalone builder did not change. The main Poker
   site, player profile, library and unrelated pages do not import it.
3. **Real keyboard transitions in browser QA.** Updated the existing
   `_tests/poker_hand_review_browser.py` offline Playwright suite:
   - Seed focus on the following known link, then require a real
     Shift+Tab to focus the preceding summary, rather than treating
     `summary.focus()` as proof of keyboard navigation.
   - Require `:focus-visible` on the summary and the next link.
   - Verify Enter and Space open and close the native disclosure,
     followed by a real forward Tab to the Continue link.
   - Check the focused parent exercise has the new 2-pixel outline.
   - After direct fragment navigation, check the review arrives
     below the sticky header and that the document does not overflow.
   - Wait for local fonts to settle before the header/anchor
     measurement, and retain the local-only intercepted requests,
     no JavaScript, no cookies, no outbound services and four
     viewport-size scenarios.
4. **Regression guard.** Added
   `_tests/test_turn158_keyboard_focus.py` to ensure the focus styles
   and real Tab tests remain in place, the browser script compiles,
   and versioned CSS links match the actual asset bytes. Added
   four negative controls for removed visual cues and simulated
   focus/navigation.
5. **Local release checklist.** Registered the new Python regression
   module in the existing manually invoked
   `_scripts/local_release_checks.py`.

## Verification boundary

The work is limited to the scoped CSS, the two published standalone
HTML files' CSS version strings, the offline browser test, the new
static regression module, its local checklist registration and
this report. The site content, hand exercises, evidence disclosures,
guide links, factual and source-review dates, article metadata,
main sitemap and both RSS feeds remain unchanged.

**Performed:** live browser read-only navigation and pointer checks,
isolated local Chromium keyboard checks at four widths, GitHub file
comparison and versioned-asset consistency checks.

**Not performed:** the full repository offline Playwright runner
against all published HTML and assets in one local checkout, the full
local deterministic Python build, broad historical tests or
real-device/assistive-technology testing. This session's container
cannot clone the GitHub repository or navigate to a fake intercepted
HTTPS origin due network and browser-administrator restrictions.
These limitations prevent any claim that the end-to-end browser suite
passed.
