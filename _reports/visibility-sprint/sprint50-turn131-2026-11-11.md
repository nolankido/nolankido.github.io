# Turn 131: Make common acronyms find the relevant published work

Date: November 11, 2026

Baseline: `2c0aa1e0b690734b8f07a7b83a7251ff9c39f4af`

## Observed reader problem

The site-wide `/find/` page already filters public titles, summaries, section
headings and addresses locally. A source-backed query check showed no results
for three short terms that are common to the site's existing subject matter:
`WSOPC`, `SEO`, and `GEO`. The same check correctly found content for longer
phrases such as `WSOP Circuit`, `gaming laptop`, and `AI Search`. It also
returned no results for `wine` and `chess`, which do not yet have corresponding
public site material. Returning unrelated pages for those topics would be
misleading. This is a documented search-function gap, not measured visitor
behavior or search-engine ranking evidence.

## Improvement

- Added `find_aliases` to the existing public page manifest for exactly three
  articles: `WSOPC` for the tournament-trip budget and Thunder Valley poker
  guide, and `SEO` and `GEO` for the public website-visibility case.
- Kept the aliases public and legible: matching Find cards now show a small
  **Related search terms** line, so a reader can see why an acronym matched.
  The website case discusses technical search improvements and the separate
  unmeasured question of AI-answer citations. These labels do not turn it into
  a comprehensive SEO or GEO guide.
- Extended the existing local search scorer to match those explicitly
  declared acronyms, including mixed queries whose other words match the
  same page. The original title, summary, section, and address matching
  remains intact, with ordinary explicit text ranked ahead of alias-only
  matches. Section jumps can also combine a page alias with a real heading.
- Updated the Find scope explanation to disclose the limited acronym set.
  Validated aliases as short, distinct, uppercase acronyms only on eligible
  public pages. Invalid, duplicated, long or nonpublic aliases fail the build.
- Added a focused regression with genuine search queries, unrelated topics,
  negative source fixtures, rendered labels and the existing local-only
  privacy contract. Registered it in the manual release checklist.

No article content, publication dates, biographical assertions, sitemap URL,
identity schema, external network request, paid service, form, saved query,
query-string transport, scheduled task or GitHub Actions workflow was added.
