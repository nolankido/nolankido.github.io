# Turn 113: Live manual-copy audit and repeatable browser handoff test

Date: November 10, 2026

Baseline: `eff5fd61c614aad7c0314c6fffe937cd0753c9bb`

## Why this turn

Turns 111 and 112 added honest native-Copy and incomplete-selection
feedback. Their regression tests dispatched simulated DOM events. They did
not prove that an actual browser keyboard command, text selection and
clipboard destination would behave the same way.

## Live browser observations

In an isolated cloud Chrome tab of the public
`https://nolankido.com/technology/task-brief/` page, all five inputs
contained invented planning-meeting text with no personal identifiers.
The actual UI demonstrated these results:

1. **Assemble my brief** produced six preview sections and the complete
   matching plain-text result.
2. **Select text manually** focused the result textarea and displayed
   the selected-but-not-copied cue.
3. The browser's actual **Ctrl+C** command changed the status to
   **Copy command detected**, without falsely claiming a verified paste.
4. Selecting only the word **PURPOSE** changed the cue to **Full brief no
   longer selected** and directed the reader to reselect everything.
5. **Ctrl+C** with that partial selection displayed the distinct warning
   that only part of the brief might have been copied.
6. Reselecting through the visible button restored the full selection
   guidance. Selecting **PURPOSE** again and pressing **Ctrl+A** also
   restored the complete-selection guidance.
7. A visual inspection confirmed that the incomplete-selection cue was
   readable directly above the focused textarea on a desktop viewport.

The browser denied navigation to a disposable, non-network paste target.
No alternate route was attempted. **A real paste destination was not
verified in this session**, and no clipboard contents were read.

## Permanent improvement

Add `_tests/task_brief_copy_handoff_browser.py` as an **opt-in,
disposable Chromium regression**. It uses committed page markup, the
committed builder JavaScript, local fictional input, an isolated headless
browser context, and a deny-all network route. The test is designed to
check the browser's native full Copy and paste, partial Copy and paste,
keyboard reselect and complete Copy again, stale-result invalidation,
and no cookies or remote requests. It does not call an AI service or
load external page resources.

The repository's existing `--browser` option automatically includes
files named `*_browser.py`, so no scheduled workflow or default browser
requirement is introduced. Run this specific test manually when a local
headless Chromium process is permitted:

```sh
python _tests/task_brief_copy_handoff_browser.py
```

Set `CHROMIUM_PATH` to a known local Chromium binary only if needed.
This optional test is a **future executable check**, not a claimed
browser-pass receipt for this turn. In the current executor the local
Chromium launcher failed before opening a page because the operating
system denied its process-socket operation. The independent cloud UI
checks above passed, but the end-to-end paste assertion remains open.
