# Turn 137: Connect homepage AI evidence directly to the project example

Date: November 12, 2026

Baseline: `abb95a5d6cf3f1c38579ba1f16213bfd560844d4`

## Observed visitor gap

The homepage's first evidence section had a **Practical AI / Reproducible
audit** card. Its primary link correctly opened the independent archived
reply audit, which includes deliberately damaged control examples and a
clear warning against treating limited checks as business outcomes. The
underlying Review Reply Writer project example was already linked farther
down the homepage and from within the audit itself, but readers at the first
evidence card had no immediate route to that project's actual documented
workflow. Reaching it required finding a later card or another page link.

This is an observable information-architecture opportunity, not evidence
that visitors were dropping out or that search engines were under-ranking
the project.

## Improvement

- Keep the independent audit as the evidence card's primary heading link.
  Preserve its wording and its explicit fictional-fixture and outcome limits.
- Add a separate, plainly named **See the project's fictional double-charge
  example** route to `/technology/local-ai-review-replies/#reply-example`
  immediately after the audit caveat. That native destination already has a
  real source-linked application example, a fictional review, and human
  approval boundaries. No new model result or real-customer claim is made.
- Give this secondary link its own line, a 44-pixel minimum touch target,
  wrapping for long labels, and a visible keyboard-focus outline, using the
  existing homepage-specific stylesheet. Do not change the global card
  layout or move the existing evidence sources.
- Add five focused tests for separate audit-versus-project routes, unique
  anchored destination, source fidelity, metadata, touch/keyboard behavior,
  and negative controls against missing links or misleading factual claims.
  Register the tests in local-only release checks.
- No GitHub Actions, new services, tracking, external uploads, credentials,
  private project names, page dates, canonical URLs or structured identity
  claims were added.
