# Turn 46: explain the free visibility measurement workflow on the public Technology page

Reviewed November 5, 2026. Starting `main` commit: `6b4591c62d0bc8395f7b54d760cfbfc9d29c41f4`.

## Why this turn

Turns 43 through 45 published an offline, standard-library-only Google Search Console CSV analyzer and documented its guarded monthly measurements. Visitors to `/technology/` could find the download in one long paragraph deep inside a public release case, but the page did not explain the practical sequence or offer an introductory shortcut to that material. A free working tool is more useful when someone can understand the inputs, command, results and limits without reading a repository report first.

This is a public **instructional improvement**, not a claim that the author's own traffic increased. Google's [Performance-report data documentation](https://support.google.com/webmasters/answer/17011364) distinguishes property-level from page-level aggregation. Its [export guidance](https://support.google.com/webmasters/answer/12919797) describes row limits and how unavailable values may become zeros in downloads. These documented restrictions are visible in the guide and reflected in the published Python program.

## What changed

1. `_source/technology/home.html` and its generated public counterpart `technology/index.html` now link from the introductory section to `#free-visibility-check` with an explicit promise of a free, private Search Console method. The existing three-choice grid and Technology navigation remain intact. The link is early in page order; no above-the-fold mobile claim is made without a viewport check.
2. The existing website-visibility case includes a four-step walkthrough: export an entire month under known filters, run the offline Python checker, distinguish property chart totals from observed Pages rows and visible-query lower bounds, and compare later periods without asserting causation.
3. A Windows PowerShell example uses the actual released command-line interface and `mdy` date option. The mobile-friendly `worksheet` / `pre` style already wraps long command lines in this site. No new JavaScript, CSS, form, cookie, event tracker, subscription, or data collection was added.
4. The walkthrough links Google's first-party source documentation and the three actual tool release pull requests ([initial tool](https://github.com/nolankido/nolankido.github.io/pull/199), [full-month chart checking](https://github.com/nolankido/nolankido.github.io/pull/200), and [explicit date formats](https://github.com/nolankido/nolankido.github.io/pull/201)). A code link above the new section remains the sole visible download link, avoiding redundant calls to action.
5. `_tests/test_turn46_visibility_guide.py` protects the anchor, four-step order, exact source-to-public guide parity, source links, key interpretation boundaries and representative negative controls. The 16 existing synthetic Search Console tool tests remain relevant and unchanged.

## Release limits

The author has not supplied raw Search Console exports, so this page presents a **method**, not simulated measurements dressed up as results. A complete month of dates does not prove the property, Web Search filter, country/device filters, data freshness or export consistency. The on-page guide deliberately explains that a sum of Pages rows does not reproduce the property's chart when aggregation or row limits differ. It does not infer user behavior, ranking changes, valuable leads, or a causal effect from a published HTML change.

This turn changes only the authored Technology hub, its public counterpart, one focused test and this public release record. The existing canonical URL, `dateModified` day, sitemap routes, Person identity, article dates and other pages stay unchanged. Publication requires reviewed GitHub changes and a read-only live-byte comparison before deployment is claimed. No GitHub Actions, cron or paid API was introduced.
