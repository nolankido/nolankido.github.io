# Visibility sprint Turn 157: Usable hand-review disclosures and direct lesson links

Date: November 16, 2026
Baseline main: `b62141f668540bce73cc668ca54b4b96c2a662ed`

## Observed issue and decision

Turn 156 added three native, outcome-independent review questions inside two
already published Portland Meadows written companions. Their revealed answer
was a direct `<p>` inside `<details class="poker-details">`. Existing
`assets/poker.css` pads `.poker-details > div` but has no corresponding
padding rule for a direct answer paragraph. The answer consequently sits
almost against the disclosure border.

An **isolated local Chromium reproduction** using those exact existing
`.poker-details` rules measured a 1-pixel answer-to-border offset
at 320, 390, 768 and 1440 viewport widths when the answer was open.
This is a CSS/markup problem, not evidence of broken live traffic or a
full-page accessibility audit.

The corresponding Turn 156 exercises also linked to separate study
guides only farther down in the hand discussion. A reader could reveal
the evidence check, but did not have an immediately adjacent
keyboard/touch-accessible next step.

## Implemented

- Added one narrowly scoped stylesheet,
  `assets/poker-hand-review.css`. The styles apply only under
  `.poker-episode-companion .poker-hand-review-check`, leaving site
  hubs, other Poker guides, the library and profile pages unchanged.
- Added inset padding to direct answer paragraphs, a 44-pixel minimum
  summary target, clear 3-pixel `:focus-visible` styles for summary
  and next links, overflow wrapping, target highlighting and
  `scroll-margin-top` for existing deep links. A small-screen
  media rule reduces padding without hiding text. Print styles
  keep the answer readable.
- Added an immediately visible, native `Continue:` link below each
  evidence disclosure:
  - `#hand-64o-review` to the 6–10 BB small-blind study section
    `/poker/six-to-ten-bb-tournament-decisions/#bridge-sb`.
  - `#hand-77-review` to the 10–20 BB stack-depth comparison
    `/poker/short-stack-decisions/#depths`.
  - `#standoff-second-review` to the chip-EV/ICM exercise
    `/poker/short-stack-decisions/#icm-call`.
- The single manually owned Episode 1 builder now fingerprints the
  standalone stylesheet from its Git blob identity and adds the
  same content-versioned link to both companion pages. The Stand Off
  builder inherits this shell; the CSS is not added to the main site
  generator or to every Poker article.
- Extended the Turn 156 regression contract to require exactly the
  correct immediate next link for each question, retaining its
  original hand facts, answer text and negative controls.
- Added `_tests/test_turn157_hand_review_accessibility.py` to the
  manual local release checklist, verifying CSS scope/version, markup,
  hand-to-lesson fragment integrity, standalone source/render parity,
  revision dates, archived evidence dates, sitemap/RSS and deliberate
  broken-link/style mutations.
- Added `_tests/poker_hand_review_browser.py`. The existing
  `--browser` option automatically finds this file. It intercepts
  all requests locally, disables JavaScript, and specifies 12
  keyboard/fragment journeys at 320, 390, 768 and 1440 pixels, with
  no external services, tracking or cookies.

## Evidence and verification completed

**Targeted isolated Chromium reproduction** (locally runnable in this
session, using the exact new CSS bytes and a matching exercise fragment):

| Width | Answer padding after fix | Summary focus outline | Direct link target | Horizontal overflow |
|---|---:|---|---|---|
| 320 px | 12.8 px | 3 px solid | 65.4 px tall | None |
| 390 px | 12.8 px | 3 px solid | 65.4 px tall | None |
| 768 px | 16 px | 3 px solid | 44 px tall | None |
| 1440 px | 16 px | 3 px solid | 44 px tall | None |

Enter opened the disclosure, Space closed it, and keyboard focus
remained visible on the next link in all four isolated scenarios. This
reproduction was not the complete live page or a screen-reader run.

**GitHub versioned-file verification:**

- Both committed companion public HTML files contain the updated
  authored body **exactly once** and the same versioned CSS link
  `/assets/poker-hand-review.css?v=225dc8e31c97`. Its version
  matches the actual Git blob SHA prefix for the exact CSS bytes.
- Removing just the added `Continue` paragraphs from the authored
  sources reproduces the previous source files byte-for-byte.
  Removing those links and the one CSS link reproduces the old
  compiled HTML files byte-for-byte.
- All three linked guide fragments already exist in the committed
  guide pages and use canonical on-site paths.
- The original November 2 and November 4 article publication dates,
  November 16 modification dates, canonical identities, video
  links, source claims and original hand headings are unchanged.
- The complete site sitemap, Poker RSS and combined writing RSS
  were not modified. The archived Episode 1 source-review
  date remains November 4, 2026.
- No main-manifest CSS asset, GitHub Actions workflow, cron service,
  paid API, or background automation was introduced.

**Not executed:** the new full-site offline Playwright script, the
full Python site builders and historical unit suites, HTML5 parser and
real-device/screen-reader audit. Those need a full local checkout.
The isolated Chromium test should not be reported as complete
production responsive or keyboard certification.

## Reproducible release checks

From a local checkout with the existing Playwright dependencies:

```sh
python _scripts/build_poker_episode.py --check
python _scripts/build_standoff_episode.py --check
python _scripts/build.py --check
python -m unittest discover -s _tests -p 'test_turn156_hand_review_exercises.py' -v
python -m unittest discover -s _tests -p 'test_turn157_hand_review_accessibility.py' -v
python _tests/poker_hand_review_browser.py
python _scripts/local_release_checks.py
```

The browser script uses the existing local request-handler and host
`https://nolankido.test` with intercepted requests. It does not
visit YouTube, send analytics, or require local HTTP services.

## Live verification and next improvement

After release, verify the asset and the three new next-study links
on the public Episode 1 and Stand Off pages, with the answers
remaining collapsed by default. Run a complete offline browser
and screen-reader check on a local checkout when available.
Only then decide whether any heading focus, sticky header, or
mobile overflow problems require broader CSS changes.

This improves navigation and presentation, but does not establish
higher watch time, learning outcomes, search impressions,
AI-assistant citations, subscriptions, or poker profitability.
