# Turn 130: Give a missing-link visitor a clearer recovery path

Date: November 11, 2026

Baseline: `63b682ac65081718cc4e7706691179305cf74a24`

## Observed issue

The site's custom 404 response already returned an actual HTTP 404 and had a
search link, but its visible content was a single generic sentence plus Home,
Search and Contact links. A visitor arriving from an old or mistyped link had
to make another navigation decision without seeing what kind of work this site
contains. That is a usability opportunity, not a measured search or bounce-rate
problem. The working Find filters and their separately registered poker records
were checked and intentionally left unchanged.

## Scoped change

- Replaced the single-line 404 body with an accessible recovery heading and
  clearly prioritized routes to the site's existing local Find page, Start
  Here, and Home. No query is collected or stored on the error page, and it
  does not read or echo a possibly sensitive missing address.
- Added three short, truthful routes using the site's existing responsive card
  presentation: practical AI projects and tools, public poker videos and
  learning, and Nolan Kido's background and inspectable evidence. The poker
  route jumps to the already published video section.
- Kept a direct broken-link report path with a reminder not to send sensitive
  records. The copy explains the privacy boundary of existing Find filtering.
- Updated only the 404 metadata description and modification date. Preserved
  the page URL, its `noindex, follow` directive, canonical, JSON-LD identity,
  status handling and sitemap exclusion. No redirect, client script, external
  service, tracker, form, scheduled task or GitHub Actions workflow was added.
- Added a focused regression covering source, generated content, native
  headings, public destinations, `noindex`, sitemap exclusion, and deliberately
  damaged link/heading/card controls. Registered it in the manual release
  checklist.

## Verification

- Rebuilt 231 generated files; precisely one generated HTML file changed.
- Focused 404 tests: **4/4 passed**, including negative controls.
- Direct public request for a deliberately nonexistent route returned **HTTP
  404** before release. This checks current hosting behavior, not every future
  Cloudflare configuration.
- The public internal-link audit saw **14,005 internal links across 207 HTML
  pages** with zero broken routes or fragments. SEO checks found zero errors
  across **202 sitemap URLs**, and HTML5 parsing found zero failures across
  **207 pages**.
- A fresh local environment initially lacked the existing `html5lib` test
  dependency. It was installed into the test environment and the release
  checklist was rerun. The first suite passed 64 of 65 groups and failed one
  import; the subsequent full manual run passed **65/65 groups**, with no
  GitHub Actions invoked. These are programmatic checks, not a completed
  device or screen-reader study.
