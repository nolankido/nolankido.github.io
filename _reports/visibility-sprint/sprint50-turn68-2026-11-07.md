# Turn 68: Keep standalone section arrivals clear of the sticky header

Date: November 7, 2026

Baseline: `d1c26a5cca87690d9dd2d22fe8e78cc2127cae7d`

## Observed reader problem

Turn 67 made the section headings on five source-validated standalone pages searchable. Its enlarged-text checks covered Find results, while destination-arrival checks used ordinary text. Extending the actual keyboard journey to enlarged-text destinations revealed a separate problem on two pages: the independent reply audit and Nolan Kido's player profile.

With a 320-pixel viewport, 200% root text size and expanded text spacing, the `invented offer` search shortcut put the reply heading about **83 pixels behind the sticky header**. The `tournament media` shortcut put the profile heading about **98 pixels behind it**. Both pages fitted the viewport horizontally, so a width-only check would miss this defect.

The same offset problem affected both native Skip to content links and the existing `/poker/nolan-kido/#creator-introduction` bookmark linked from Bio. At 390 pixels the two search-target headings were also obscured. At 1440 pixels with enlarged text, the profile heading still began about 30 pixels behind its header, so a mobile-only repair would be incomplete.

These are local browser measurements, not reader analytics. The heading labels, destinations, search matches and source material were already correct.

## Focused improvement

`assets/standalone-section-arrivals.css` adds native scroll clearance only to:

- The two pages' `#main` skip targets.
- All six player-profile H2 headings and all nine reply-audit H2 headings.
- The preserved profile section bookmark `#creator-introduction`.

The rules use the exact owner classes `.page-poker-player` and `.page-review-reply-evidence-audit`. The reply headings are inside `.reply-independent-case`, not the profile's `.article-body` wrapper. A DOM-ancestry unit check protects that distinction.

A base `2rem` scroll margin covers enlarged desktop text. At widths of 1050 pixels or less, `5rem` complements the site's existing 180-pixel scroll padding. The font-relative margin grows with reader text size. No JavaScript scroll handler, header-height change or shared stylesheet modification is introduced. The asset is **619 bytes** and has no image, font, import or other network dependency.

The two independent builders inject one content-versioned stylesheet link each and reject inherited duplicates or ambiguous head anchors. The asset is registered in the existing read-only public-byte inventory. `AGENTS.md` records the two-owner rebuild requirement so a later CSS edit refreshes both pages' links.

Only `poker/nolan-kido/index.html` and `technology/review-reply-evidence-audit/index.html` change among public HTML files. Removing the one new stylesheet link restores each baseline document byte-for-byte. Both editable sources, all existing IDs and links, search JavaScript, Find, feeds and sitemap remain unchanged. No title, description, authorship, identity record, publication date or modification date changes for this styling repair.
